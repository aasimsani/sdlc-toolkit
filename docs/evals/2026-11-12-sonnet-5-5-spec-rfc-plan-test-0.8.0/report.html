### Phase 2 — Quoting
Add the AC3 check first (the two exact rows `INV-002,"Acme, Inc.",310.50,paid` and `INV-004,"Initech ""West""",4500.00,open`) and watch it fail, because phase 1 prints them unquoted.

Create `lib/csv.awk` holding one function: `csv_field(s)` returns `s` unchanged unless it contains `,` or `"`; otherwise it does `gsub(/"/, "\"\"", s)` and returns `"\"" s "\""`. In `bin/invoices`, load it by putting its text in front of the CSV awk program: `awk -F '\t' "$(cat "$root/lib/csv.awk")
<program>"`. Reason: awk can't mix `-f file` with an inline program, and this is plain POSIX with no `/dev/stdin` dependency. I checked on this machine's awk (version 20200816) that both this form and `-f lib/csv.awk -f /dev/stdin` work. The CSV branch then prints `csv_field($1) "," csv_field($2) ...` for each field. This keeps the RFC's chosen design (option A, quoting in `lib/csv.awk`) and only changes how the file is loaded. If that load fails on the CI image, the RFC's fallback applies: move the function inline into `bin/invoices`.

Status: draft, for Lee's review
Inputs: [intent](intent.md), [spec](spec.md), [rfc](rfc.md) (all approved)

## Scope
Deliver `bin/invoices list --csv` in the two phases the RFC approved. This plan adds the work breakdown, the tests, and the order of work. It doesn't change the spec or the RFC.

## Review note
This plan has not had a Goldfish review. EGM and the testing toolkit aren't installed on the machine that drafted it. I chose the tests myself, so please check the test list below against the acceptance criteria.

## Approach in one paragraph
`bin/invoices` currently runs one inline awk program. `--csv` becomes a second output mode of `list`. It uses the same `--status` filter and the same `awk -F '\t'` split, and it prints each field as the string it was read. Amounts are never converted to numbers, as CLAUDE.md requires, so `4500.00` and `310.50` keep their trailing zeros. PR 1 prints plain rows. PR 2 adds `lib/csv.awk` and routes every field through `csv_field`.

## Work breakdown

### PR 1 — REP-101: `--csv` output (R1, R2, R4)
1. **Capture the AC4 baseline first, before any code change.** Run `bin/invoices list > tests/golden/list.txt` and `bin/invoices list --status open > tests/golden/list-open.txt` on the unchanged script, and commit them as the first commit of the PR. Capturing them after the change would prove nothing.
2. Edit `bin/invoices`:
   - Add a `csv=0` variable and a `--csv) csv=1; shift ;;` case to the option loop. The option works in either order with `--status`.
   - Update the usage text in the header comment and the usage message to `invoices list [--status open|paid] [--csv]`.
   - When `csv=1`, run an awk program with `-F '\t' -v OFS=','` that applies the same filter (`NR == 1 || status == "" || $4 == status`) and prints `$1,$2,$3,$4`. Row 1 of the data file is the header, so the filter gives the header row for free.
   - When `csv=0`, run the existing awk program unchanged.
3. Add tests (see the test list) and run `sh verify.sh`.

**Interim state:** after PR 1, rows for `INV-002` and `INV-004` are not valid CSV, because quoting arrives in PR 2. Don't announce the feature to Finance until PR 2 has merged. Both PRs can merge on the same day.

### PR 2 — REP-102: quoting (R3)
1. Create `lib/csv.awk` with one function:
   ```awk
   function csv_field(s) {
     if (s ~ /[",]/) { gsub(/"/, "\"\"", s); s = "\"" s "\"" }
     return s
   }
   ```
2. Change the `--csv` branch of `bin/invoices` to load the file with `awk -f "$root/lib/csv.awk"`, and print `csv_field($1)`, `csv_field($2)`, `csv_field($3)` and `csv_field($4)` joined by commas. The main program needs a second `-f` source, because POSIX awk doesn't mix `-f` with an inline program text. Pass it as a here-document on `-f /dev/stdin`.
3. Add the quoting tests and the 2,000-invoice timing test.
4. If the two-source `awk -f` call misbehaves on the CI image, use the RFC fallback: move `csv_field` inline into the awk program in `bin/invoices` (option B), keep the tests unchanged, and note the change in the PR description.

## Decision for Lee: how to load `lib/csv.awk`

# Spec: CSV export for the invoice list

Intent: [intent.md](intent.md) (approved by Lee, 2026-11-02)

## Summary
Add an `export` subcommand to `bin/invoices`. It prints the same invoices as `list`, as RFC 4180 CSV, so finance can redirect it to a file and open it in a spreadsheet.

## Interface
```
bin/invoices export [--status open|paid]
```
- Writes CSV to stdout. Finance saves it with a shell redirect: `bin/invoices export > invoices.csv`. There is no `--output` flag.
- `--status` behaves exactly as it does for `list`: the header is always kept, and only rows whose status equals the value are kept. Any other value yields the header only, same as `list` today.
- Reads `data/invoices.tsv`, or the file named by `INVOICES_FILE`, same as `list`.
- The usage line and the header comment in `bin/invoices` are updated to mention `export`.
- `list` output does not change.

## Output format
- Columns, in order: `id,customer,amount,status`. The first row is always this header, taken from the input's first row.
- One CSV row per input row, in input order. Row count equals what `list` prints for the same options.
- Fields are separated by commas. Records end with CRLF (RFC 4180).
- A field is wrapped in double quotes if it contains a comma, a double quote, a CR or an LF. Inside a quoted field every double quote is doubled. Other fields are written bare.
- Encoding is passed through unchanged (UTF-8 in, UTF-8 out). No BOM.
- Amounts are copied through as the original decimal string, for example `1200.00` stays `1200.00`. They are never converted to a number or reformatted, per the project convention.

Example, from the current data:
```
id,customer,amount,status
INV-001,Northwind Traders,1200.00,open
INV-002,"Acme, Inc.",310.50,paid
INV-003,Globex,89.99,open
INV-004,"Initech ""West""",4500.00,open
```
(Each line ends in CRLF.)

## Behaviour on bad input
| Case | Result |
|---|---|
| Unknown option | Message on stderr, exit 2, no stdout (same as `list`) |
| `--status` with no value | Same failure as `list` today; not changed by this feature |
| Missing or unreadable data file | Non-zero exit, error on stderr, nothing on stdout |
| Header-only data file | Header row only, exit 0 |
| Row with fewer than four fields | Missing fields are written as empty, so every row has four columns |

## Design
- Implemented in POSIX shell and awk in `bin/invoices`. No new dependencies.
- One awk pass over the file, with the existing row filter shared with `list` so the two cannot drift apart. The CSV quoting is a small awk function that doubles quotes and wraps the field when needed.
- Amount is only ever handled as a string (`$3` is printed, never used in arithmetic).
- Performance: one pass with no per-row process spawns, so 2,000 rows is far inside the 5 s budget.
